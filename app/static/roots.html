④ 验证结果

提交后这里展示每个版本的双重阈值验签细节、过期判定；失败时明确指出失败版本与原因，受信 root 保持不变。

⑤ TUF 1.0.37 验签规则（本服务实现）

  • 仅支持 Ed25519（keytype/scheme 均为 ed25519）；keyid = sha256(canonical JSON(key))，不符即拒绝。
  • 版本号必须 逐次加 1：首份为受信版本 +1，之后每份 = 上一份 +1。
  • 每份候选 root 必须 同时 达到：①上一版 root 的 root 角色阈值；②自身 root 角色阈值。
  • 同一 keyid 的多条签名只计一次，重复 keyid 不得凑足阈值；未知 keyid 的签名忽略。
  • 中间版本 root 允许已过期；最终 root 的 expires 必须晚于本次更新开始时间。
  • 整链通过才替换 SQLite 中的受信 root；任一环节失败则保留原根，返回失败版本与原因。
  • 两个工作进程并发提交时，以锁内读到的最新受信 root 为起点，后到的请求不会覆盖已提交的更新。
